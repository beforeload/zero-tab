# Zero Tab Chrome Web Store Submission Guide

Use this guide when submitting Zero Tab to the [Chrome Developer Dashboard](https://chrome.google.com/webstore/devconsole).

## 1. Before you start

1. Push the latest `main` branch to `git@github.com:beforeload/zero-tab.git`.
2. Enable GitHub Pages for the repository:
   - Settings → Pages → Source: `Deploy from a branch`
   - Branch: `main` / folder: `/docs`
   - Confirm `https://beforeload.github.io/zero-tab/privacy.html` loads
3. Register a Chrome Web Store developer account and pay the one-time fee.
4. Regenerate store assets and the ZIP package:

```bash
chmod +x store/assets/generate-assets.sh
./store/assets/generate-assets.sh
node --test tests/builder-digest.test.js
```

## 2. Upload package

| Field | Value |
| --- | --- |
| ZIP file | `dist/zero-tab-webstore-1.2.0.zip` |
| Version | `1.2.0` |
| Manifest root | `manifest.json` |

Never upload `dist/zero-tab.pem` or any private signing key.

## 5. Privacy practices

In the dashboard privacy form, declare:

- **Single purpose:** developer-focused new tab workspace
- **Data collected locally:** tab URLs, titles, favicons, saved links, preferences, report cache, read state
- **Optional remote data:** public JSON feeds from `raw.githubusercontent.com` only after explicit user opt-in
- **No sale, no ads, no analytics**
- **Limited Use:** Chrome API data is used only for the extension's user-facing functionality

Full policy text: [`store/privacy-policy.md`](privacy-policy.md). The page published through GitHub Pages is [`docs/privacy.html`](../docs/privacy.html).

## 7. Permission justification quick reference

| Permission | Why |
| --- | --- |
| `tabs` | Read, focus, and close user-selected tabs |
| `storage` | Saved for later, preferences, report cache |
| `favicon` | Show local favicons without third-party requests |
| `https://raw.githubusercontent.com/*` (optional) | Fetch public Follow Builders JSON feeds after user opt-in |

## 8. Distribution settings

Recommended first release:

- Visibility: Public
- Regions: all supported countries
- Publishing: manual review, then publish when approved

## 9. Known blocker before final approval

AI Builder Daily Report displays public content from the Follow Builders repository. That repository does not currently include a repository-level license for public feed display. Before the final public release, obtain written permission from the feed owner or remove/replace the feed source.

## 10. After approval

1. Reload the extension locally only when testing updates.
2. Bump `version` in `extension/manifest.json` before each new upload.
3. Re-run `./store/assets/generate-assets.sh` when UI screenshots change.
4. Keep `store/PUBLISHING_CHECKLIST.md` updated for future releases.
